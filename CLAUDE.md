# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repository is

`github.com/iceymoss/agent-runtime-go` — a composable, provider-agnostic **library** (not a service). It executes the model/tool loop; the *consuming application* owns model credentials, prompts, tool implementations, permissions, storage, and business APIs. Public API is `v0.x` and may still break, but every exported symbol is documented and covered by tests.

Two Go modules live here:

| Module | Path | Notes |
|---|---|---|
| library | `/` (root) | `go 1.25.0`, only two direct deps (`santhosh-tekuri/jsonschema/v6`, `go.yaml.in/yaml/v3`) |
| iCoder demo | `demo/icoder` | separate module with `replace ... => ../..`; Bubble Tea TUI + Cobra + SQLite; needs `CGO_ENABLED=1` |


## Architecture

### Dependency rule — enforced by tests, not convention

`deps_test.go` fails the build on violations. Read it before adding an import:

1. **The root package `agent` must not import any subpackage of this module.** It is the portable core; everything else depends on it, never the reverse.
2. No package may import `.../internal/...`.
3. No production package may import `agenttest` (test-only helpers).

Consequence: shared types live in the root. Subpackages alias them rather than redefining (`durable/types.go` does `type Checkpoint = agent.Checkpoint`). If a subpackage needs the root to know about it, the design is wrong — invert it into an interface in the root.

### Root package (`*.go` at module root)

One file per concern; the loop itself is `agent.go`.

- `agent.go` — `Config`, `Agent`, `New`, `Run`, `runDurable`, `execTools`. `Agent` is **stateless and safe to share across goroutines/sessions**; all per-turn state lives in `RunRequest`/`RunResult`.
- `llm.go` — the `Model` port (`Name`/`Capabilities`/`Stream`), `GenerateRequest`, `Response`, `Usage`, `ToolChoice`, sentinel errors (`ErrAgentConfigInvalid`, `ErrToolNotAllowed`, `ErrToolInputInvalid`, `ErrLoopDetected`, ...).
- `message.go` — `Message`/`ContentPart`/`ToolCall`/`ToolResult`/`Role`/`FinishReason` and constructors.
- `tool.go` — `Tool` interface, `Registry` (mutable, assembly-time) → `ToolSet` (immutable snapshot with a content-addressed `Version()`), JSON Schema compilation, allowlists, `ToolSuspension`.
- `toolfunc.go` — `NewTool[T]`/`MustNewTool[T]`: schema generated by reflection over the input struct. Non-pointer fields without `omitempty` become `required`; strict (`additionalProperties: false`) unless `WithoutStrictSchema()`.
- `step.go` — `StepResult`, `StopCondition` combinators, `ContextBudgetExceeded` (reserve = 20% under 100k window, fixed 20k above).
- `loop_detection.go` — sliding-window signature repeat detection; defaults window 4 / threshold 2. Window > `MaxSteps` is rejected at `New()` because detection would silently never fire.
- `recovery.go` — durable primitives: `Checkpoint`, `RunSnapshot`, status/phase state machine (`ValidateRunTransition`), canonical digests, and `ToolExecutionKey` (the stable key downstream systems dedupe on).
- `runtime_definition.go` — immutable `RuntimeDefinition` + reproducible artifact digests; `NewAgent()` materializes an `Agent` from one.
- `stream.go` / `event.go` — chunk aggregation into a `Response`; `Observation` emission (bounded, non-blocking, **lossy** — never an authoritative event log).
- `store.go` — in-memory `Store` reference implementation of the session/message ports.

### Run loop semantics (`Agent.Run`)

```
history -> nextRequest -> Model.Stream -> collectStream -> validate Response
   |                                                          |
   |<- append assistant msg + tool msg <- execTools <- tool calls
   -> stop checks: finish reason / suspension / loop / context budget / stop conditions
```

Two orthogonal outcome fields that are easy to confuse:

- `RunResult.Outcome` — `completed` / `suspended` / `failed`. A non-nil error always forces `failed`.
- `RunResult.StopReason` — *why* it stopped: `complete`, `output_limit`, `tool_suspended`, `tool_stop_turn`, `loop_detected`, `context_budget`, `max_steps`, `stop_condition`.

Hitting `MaxSteps` while the model is still calling tools is **not an error** — it returns `suspended` + `max_steps`. Only `FinishStop` without tool calls is a genuine final answer.

Other invariants worth preserving when editing:

- `RunResult.Messages` holds *only* messages added during this run — the application persists them.
- `ToolResult{IsError: true}` is a model-visible, correctable error; a non-nil Go error terminates the attempt with the cause intact and is never swallowed.
- `AllowedTools == nil` means every registered tool; `[]string{}` explicitly means no tools.
- `ToolRepairLimit` (default 1, hard max 2) bounds invalid tool calls fed back for repair before the run fails.
- Durable execution does not guarantee exactly-once side effects; downstream dedupes on `ExecutionKey`.
- Prompts, Skills, and model output are **not** permission boundaries — enforce in tools and adapters.

### Subpackages (opt-in, each documented in `docs/packages/*.md`)

`providers/openaicompat` (SSE, tool-call fragment assembly, usage normalization, `ModelError` classification) · `provider` (multi-model catalog) · `prompt` · `context` (history normalization, compaction plans, token budgets) · `message` (aggregation + revision CAS) · `session` (`SessionAgent`: claim/lease/worker/merge/resume/drain) · `durable` (snapshots, leases, fences, effect + usage ledgers) · `permission` (allow/deny/ask) · `tool` (advanced lifecycle, effect ledger, `agent_bridge`) · `event` (bus, outbox, inbox, replay) · `skills` (untrusted instruction catalog) · `mcp` (stdio + streamable HTTP) · `coordinator` (immutable capability composition, digest-keyed cache) · `subagent` · `app` (readiness, bounded shutdown) · `agenttest` (conformance suites: `agenttest.TestModel`, `agenttest.TestTool` — new adapters should run these).

## Conventions

- **Test package split is meaningful.** `xxx_test.go` in `package agent` is white-box (internals, regressions); `xxx_external_test.go` in `package agent_test` pins the *public* API surface. Every subpackage tests through `package <name>_test` — keep it that way so the exported contract stays honest. Table-driven with `t.Run` subtests is the house style.
- `audit_regression_test.go` is a regression pen for previously-audited invariants (tool-choice enforcement, repair budgets, observer deep-copies, terminal states, cancellation). Add new invariant regressions there rather than scattering them.
- `*_external_test.go` naming applies to conformance/API tests; `conformance_test.go` in `subagent` is the port-conformance suite.
- Doc comments are full sentences explaining *why* a constraint exists (see `New`, `NewLoopDetector`, `contextReserve`). Match that register; the docs site is generated from these packages' semantics.
- Everything returned from the runtime is deep-copied before crossing the boundary (`cloneMessages`, `cloneToolDefinition`, `cloneObservation`, `Clone()` on snapshots). Preserve this when adding fields — shared mutable state leaking to callers is a bug class this codebase actively defends against.
- LF endings enforced via `.gitattributes` so the gofmt gate is stable across platforms.

## Documentation is bilingual and package-scoped

`docs/` is Simplified Chinese (default site locale), `docs/en/` is English, and they mirror each other file for file. **A public API change means updating both**: `docs/packages/<pkg>.md` and `docs/en/packages/<pkg>.md`, plus `README.md` and `README.zh-CN.md` if the change is user-facing. Notable API changes also get a `CHANGELOG.md` entry under `## [Unreleased]` (Keep a Changelog format, semver with breaking changes allowed in `0.x` minors).
