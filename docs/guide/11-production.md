# 11. 上生产

## 你现在遇到的问题

功能齐了，但还差两件事：运行过程中发生的事要可靠地告诉下游系统（计费、审计、通知），以及进程重启时不能把跑到一半的运行直接掐掉。

## 可靠的事件

第 5 章的 `Observation` 是可丢的进度信号，不能用来承载正确性。要"这条事件一定会送达下游"，用 `event` 子包：

```go
import "github.com/iceymoss/agent-runtime-go/event"
```

它提供事务 outbox、claim/lease/fence 的投递语义、以及重放。关键点是 outbox 和你的业务写入在同一个事务里提交——否则总有一个窗口，业务成功了但事件丢了，或者反过来。

## 就绪与优雅关闭

`app` 子包把组件依赖图、就绪探针和有界关闭做成一套：

```go
import "github.com/iceymoss/agent-runtime-go/app"
```

关闭顺序是有意的：**先停止准入 → 取消 → 落 checkpoint → 等待 → 冲刷 → 关闭**。先停准入，正在关闭的进程才会拒绝新运行，而不是接下来又立刻掐掉它；落 checkpoint 在等待之前，才能保证被中断的运行是可恢复的而不是丢失的。

就绪探针要真的探到底层——配置了数据库不等于数据库是通的。

## 还需要你自己做的

库不管这些，它们是你的组装根的事：

- **凭据**：从哪读、怎么轮换
- **限流与配额**：谁能跑多少
- **多租户隔离**：库里的 `TenantKey` 只是一个标签，真正的隔离在你的存储和鉴权里
- **可观测性**：指标、追踪、日志脱敏
