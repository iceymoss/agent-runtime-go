# 开发者上手文档（Developer Guide）

## 状态
- 创建日期: 2026-08-29
- 状态: 已实现

## 目标

给"会写 Go、没做过 LLM 应用"的开发者一条能一路走完的主线：从一次最小调用开始，到一个能上生产的 agent，中途在**需要某个能力的那一刻**引入对应子包。

## 非目标

- **不重复包文档**（但必须给出集成代码——第一版把这两件事搞混了，导致第 8/10/11 章只有 import 语句）。18 篇 `docs/packages/*.md` 已经是"是什么 → 为什么 → 怎么用 → FAQ"的参考层，这份文档只负责"在什么位置、为什么现在需要它、最小接法"，细节一律链接过去。
- **不写伪代码**。所有片段必须是能编译的真实 API（`.claude/rules/docs.md` 的硬要求）。
- **不做 API 变更**。这是纯文档工作。
- 不覆盖 `demo/icoder` 的实现细节，那是 `docs/icoder.md` 的职责。

## 调用方故事

作为一个熟悉 Go、但没做过 LLM 应用的后端开发者，我想要一条按顺序读下来就能建成 agent 的主线，以便我不需要先读完 18 个子包文档才知道该从哪下手。

## 归属

- 位置: `docs/guide/`（中文）与 `docs/en/guide/`（英文），双语镜像
- 理由: 现有 `docs/` 顶层是按文档**类型**分的（quickstart / concepts / packages / internals / production / reference）。教程是第五种类型，独立目录比塞进顶层更清楚，也让 VitePress 的 prev/next 天然形成"连贯"。

### 每章的固定骨架

```
## 你现在遇到的问题      ← 一段，说清楚上一章结束后卡在哪
## 怎么做                ← 可编译代码 + 必要解释
## 需要注意的            ← 真实会踩的坑，没有就不写这一节
## 深入                  ← 链接到 docs/packages/<pkg>.md
```

### 写作准则

目标是**读者读一遍就懂，不用回头**。长度由内容决定，不设行数上限——写满三屏但每句都必要，好过挤成一屏却说不清。判断标准是下面这些，都可以在 review 里逐条对照：

1. **一件事只说一遍。** 同一个点不要在开头段、代码注释、注意事项里各说一次。选最合适的一处。
2. **先结论后解释。** 每节第一句就是答案，读者随时可以停下。
3. **代码能说明的，正文不再复述。** 代码下面不写"上面这段代码创建了一个 Registry"。
4. **删掉过渡和仪式。** 不写"接下来我们来看看"、"如你所见"、"值得注意的是"、"本章将介绍"、"本章小结"。VitePress 的标题和 prev/next 已经承担了导航。
5. **注意事项必须是真会踩的坑，且写清后果。** "默认的 emitter 会丢字，用户看到的答案是截断的"是坑；"请确保参数正确"是废话。想不出真坑就不写这一节。
6. **术语第一次出现就定义，之后不再解释。** tool-calling、step、suspension 各定义一次。
7. **能链接就不复述。** 包文档已经写清楚的，给链接，不摘抄。
8. **不为了对称而补内容。** 每章骨架的四段不是必填项，某章没有"注意事项"就不写这一节。

## 语义

### 正常流程

1. 读者从索引页知道这份文档的终点是什么。
2. 按顺序读 1→12，每章结束时手上的程序都能跑。
3. 任何一章都可以停下：前 3 章就是一个可用的工具型 agent，前 6 章覆盖大多数应用。

### 边界情况

| 场景 | 处理方式 |
|---|---|
| 读者只想要 10 分钟速通 | 索引页首屏给"最短路径：第 1、2、3 章" |
| 读者已经熟悉 LLM 应用 | 每章"你现在遇到的问题"一段即可判断要不要跳过 |
| 读者要找某个具体子包 | 索引页给一张"子包 → 章节"对照表；侧边栏的包文档组保持不变 |
| 概念解释与老手体验冲突 | 概念解释只在第 1、2 章出现，且用引用块标出可跳过 |

### 一致性约束

- 中英文件一一对应，同一章的结构、代码、链接必须一致。
- 代码片段与 `examples/` 和已有测试保持一致；主线程序应能对应到 `examples/hello`、`examples/tool-agent`、`examples/chat`、`examples/openai-compat`。
- 出现的每个 API 都必须在当前分支实际存在（本轮刚加的 `StreamResponse`、`ObservationOptions`、`ResponseFormat`、`PartReasoning`、`providers/retry` 都要用上）。
